# Автоматический расчёт нагрузки KINI

Локальное веб-приложение на Python для расчёта учебной нагрузки по Excel-МУПам.
Загрузка планов, настройки групп и выгрузка годовых книг работают на вашем компьютере.

## Первый запуск после скачивания репозитория

В публичном репозитории находятся исходный код и конфигурация. Учебные планы,
рабочий Excel-шаблон, загруженные файлы, локальные настройки браузера и результаты
расчётов остаются вне Git.

1. Установите Python 3.10 или новее.
2. Выполните `python -m pip install -r requirements.txt`.
3. Добавьте свои МУПы в `input/` и шаблон в `template/`; инструкции и названия файлов находятся в README этих папок. Если файлы называются иначе, измените пути в `kini_config.json`.
4. Запустите `python webapp.py --open` (на macOS/Linux можно использовать `python3`).

Интерфейс: `http://127.0.0.1:8765`. Excel и интернет для расчётов не требуются.
Остановка приложения: Ctrl+C в терминале.

Без рабочих Excel можно проверить распознавание синтетических МУПов:

```sh
python -m unittest test_webapp.NewPlanTests -v
```

Полный набор регрессионных тестов использует локальные рабочие книги. При их
отсутствии соответствующие тесты пропускаются. Программа формирует предварительную
нагрузку: неопределённые нормы и дополнительные подгруппы требуют уточнения.

## Текущая локальная конфигурация

Приложение в браузере собирает выбранные МУПы в отдельные книги по учебным годам. В каждой книге **только лист `Расчет`**. В приложении сохранены CS-26 — 8, MECH-26 — 7, PE-26 — 4, EEE-26 — 9, LOG-26 — 7: всего 35 студентов. Проверенная выгрузка этого состава находится в `output_35/`, итог 2026–2027 — 2174,9 часа заполненной нагрузки. Старый кэш браузера не подменяет обновлённый серверный выбор. `output_clean/` содержит предыдущий вариант на 64 студента; остальные папки результатов относятся к предыдущим проверкам.

Исходные файлы из Downloads не изменяются; рабочие копии находятся в `input/` и `template/`.

## Запуск

Дважды нажмите **`Открыть KINI.bat`**. Откроется `http://127.0.0.1:8765` в браузере. Окно программы оставьте открытым на время работы; для остановки закройте его или нажмите Ctrl+C.

1. Нажмите **«Выбрать файлы»** или перетащите один/несколько МУПов `.xlsx` на страницу.
2. Для каждой группы проверьте название, программу, год поступления, численность и язык. Новому МУПу нужно указать число студентов. Если год не указан в шапке, предлагается текущий год — проверьте его.
3. Если один МУП используется несколькими группами, нажмите **⧉** в карточке группы. Удаление **×** убирает группу из расчёта, сохраняя сам загруженный файл. В разделе «Источник» можно выбрать другой МУП и распознанный лист.
4. Нажмите **«Сформировать расчёт»**. Скачайте отдельные Excel или все файлы архивом. Замечания доступны на странице с поиском и фильтрами, а также отдельным JSON-файлом.

Текущие пять групп уже добавлены. Выбор групп сохраняется в этом браузере; после запуска расчёта он также сохраняется на сервере. Загрузки и результаты находятся в `.kini-app/`, каждый запуск — в отдельной папке `.kini-app/runs/`. После перезапуска программы старые файлы остаются на диске, для ссылок на скачивание в браузере нужно сформировать расчёт заново. Файлы обрабатываются на этом компьютере, интернет и установленный Excel не требуются.

Запуск из терминала:

```powershell
python webapp.py --open
```

Если порт занят, используйте `python webapp.py --open --port 8766`.

Прежний запуск без браузера тоже доступен: `generate_kini.bat` или:

```powershell
python generate_kini.py
# В другую папку, например если предыдущая книга открыта в Excel:
python generate_kini.py --output output_new
```

Для установки зависимости на другом компьютере:

```powershell
python -m pip install -r requirements.txt
```

Требуется Python 3.10 или новее и openpyxl. Установленный Excel для формирования файлов не требуется. Формулы остаются формулами, их сохранённые значения также записываются в файл; при открытии Excel включён автоматический пересчёт.

## Настройки без браузера

Для обычного использования достаточно страницы. Ручная конфигурация позволяет дополнительно задать численность по годам, исключения и нормы.

1. Положите новый файл Excel в `input/`.
2. Добавьте группу в массив `groups` файла `kini_config.json`:

```json
{
  "name": "CS-27",
  "program": "CS",
  "intake": 2027,
  "students": 12,
  "language": "KZ",
  "file": "input/МУП CS 27.xlsx",
  "students_by_year": {},
  "exclude_rows": [],
  "overrides": {}
}
```

3. Запустите генератор. Он определит все учебные годы по семестрам добавленных МУПов. В одном годовом файле могут находиться первый курс нового набора и второй курс предыдущего. Курс указан в исходном столбце D; нечётные семестры МУПа попадают в I семестр учебного года, чётные — во II.

Генератор распознаёт столбцы по заголовкам, а не по названию файла или фиксированным буквам столбцов. Поддерживаются существующие семейства CS/EEE/Logistics, Process Engineering и Mechatronics, сдвиги шапки и столбцов, добавленные дисциплины и последовательная сетка из 2–16 семестров. Можно выбрать один из нескольких листов МУПа. Простые формулы кредитов и часов (`SUM`, ссылки, арифметика) читаются даже без сохранённого кэша Excel; неподдерживаемую формулу нужно пересчитать и сохранить в Excel. Нераспознанные или неоднозначные заголовки вызывают понятную ошибку, вместо расчёта по случайным столбцам. Принципиально иной шаблон, например отдельная сетка SWS старого CS, требует адаптации.

Для годовых файлов используется год поступления из настроек группы. Шапка МУПа помогает предложить его в интерфейсе, но при противоречиях нужно проверить значение вручную.

Численность текущих групп: PE — 4, CS — 8, LOG — 7, MECH — 7, EEE — 9. Эти значения взяты из шаблона 2026–27: PE — остаток от общего потока 35 после четырёх остальных групп. Для будущих лет они сохраняются. Изменить численность отдельного года можно так:

```json
"students_by_year": {"2027": 10, "2028": 9}
```

Повторный запуск заменяет одноимённые сгенерированные книги. Ручные правки в выходном Excel не переносятся в следующий запуск — постоянные изменения вносите в настройки или копию исходного МУПа. Старые файлы других годов автоматически не удаляются; перечень результатов текущего запуска — в `output/manifest.json`.

## Что заполняется

- Лист `Расчет`: все исходные поля A:T, языковые блоки, два семестра, год, раздел магистратуры, своды кафедры, основной и почасовой фонд, подписи. Копируются шрифты, границы, заливки, ширины столбцов и объединения заголовков шаблона. Строки дисциплин добавляются по необходимости; высота адаптируется к длинным названиям. Ошибочные дубли итогов исходника не воспроизводятся.
- `СРСП`, столбец K: `=ROUND(Cстрока*1.5,6)` для обычных дисциплин.
- `Экзамен`, столбец L: `=ROUND(Gстрока*0.1,6)` для всех обычных дисциплин по заданному пользователем правилу. Пустая форма контроля в МУПе отражается в замечаниях, но не отменяет эту формулу.
- Учебная практика, столбец N: `кредиты × студенты × 0,2`, как в N25/N59 шаблона.
- Итог строки T: сумма H:S. Итоги языка, семестра и года суммируют только относящиеся к ним строки, без заголовков, повторных итогов и циклических ссылок.
- Отдельные листы `итог(основной)` и `итог(час)` временно не создаются. Нижние блоки основного и почасового фонда внутри `Расчет` сохранены; формулы в них суммируют строки этого же листа. Межлистовых ссылок в выходной книге нет.
- Часы без однозначного назначения включены в общий итог и отдельный блок «Не распределено» на листе `Расчет`, без выдуманного назначения преподавателю или виду оплаты.
- Источники каждой строки указаны в примечаниях ячеек. Подробности по группам, дисциплинам, семестрам и замечания — на странице и в `Замечания.json` (при запуске через CLI — `manifest.json`). Служебных листов в Excel нет.

## Правила объединения и часов

Сопоставление использует точные совпадения переводов названия и ограниченный словарь вариантов написания. Нечёткий поиск не применяется. Разные номера дисциплин, кредиты, язык, курс и период не объединяются. Один и тот же студент учитывается один раз в объединённой строке; кредиты и часы одного потока не складываются по числу групп.

Готовый сценарий из шаблона применяется к часам H:J при совпадении дисциплины, курса, семестра, кредитов, языка и программ с годами поступления. При точной численности используется соответствующий сценарий. При увеличении численности сохраняется подтверждённый базовый объём, а необходимость дополнительных подгрупп отмечается в замечаниях «численность потока»; это не утверждённый полный объём для увеличенной группы. Часы не исчезают только из-за роста контингента. При уменьшении численности неподтверждённое сокращение часов не производится: используются данные МУПа и замечания. Программа другого набора не подменяет указанную в образце группу.

`reference_students` хранит подтверждённую численность групп образца отдельно от текущей: CS-2026 — 8, MECH-2026 — 7, PE-2026 — 4, EEE-2026 — 9, LOG-2026 — 7. Если сумма не совпала с контингентом строки образца (например, 208 вместо 20 у физики), её часы не переносятся.

Проверенные соответствия PE «Химия 1» → общая неорганическая химия и MECH «Физика» → физика 1 описаны в `reference_matches` файла настроек. Они ограничены программой, названием и семестром; в каждом правиле есть основание. Правила не меняют семестр и кредиты МУПа. Для немецкого языка II семестра части 4+2 кредита могут объединяться в один поток на 6 кредитов, если состав и контингент совпали с образцом. Все исходные записи сохраняются в примечании; студенты и экзамен учитываются один раз. Прочие неподтверждённые составы не получают 270 часов автоматически.

Когда такого сценария нет, односеместровые часы берутся из МУПа. Совпадения часов недостаточно для объединения: состав потока должен также подтверждаться строкой образца для тех же наборов, языка, курса и периода. Неподтверждённые группы и разные часы остаются отдельными строками. Если МУП содержит общие часы на несколько семестров, они не делятся пропорционально. Прямые часы односеместровых языковых составляющих можно использовать только при полном совпадении их сумм с общими кредитами и часами маршрута.

В строках с общими объединёнными кредитами сохраняется один бюджет блока, а **каждое название показано отдельной видимой строкой** с указанием общей строки расчёта. Составляющие языковых блоков также видны в книге; основной маршрут и его составляющие не начисляются повторно. Исходные номера строк, семестры и кредиты составляющих сохранены в примечаниях и `shared_sources` отчёта. Пустые числовые поля составляющих означают, что их общий бюджет учтён в указанной основной строке. Это не утверждение о выборе первой альтернативы группой. Расхождения кредитов и часов составляющих отражаются в замечаниях; неоднозначные часы не берутся автоматически из первой строки.

Перед сохранением выполняются две проверки полноты: независимая инвентаризация исходного МУПа против распознанных записей и сверка всех этих записей с фактическими строками выходного Excel. Потеря или повтор исходной записи останавливает формирование. К каждому расчёту добавляются `Проверка МУПов и образца.md` и `.json` со сверкой всех 62 предметных строк образца, контингента, часов, семестров, кредитов и формул. В браузере они входят в ZIP-архив.

Для дипломного руководства, производственных/преддипломных практик, НИРС и аттестации без подтверждённых норм преподавательские часы не рассчитываются из студенческих часов МУПа. Кредиты и строки остаются в книге.

**Полученные книги — предварительные расчёты заполненных часов. Пустые жёлтые поля не означают отсутствие нагрузки. Например, в VIII семестре текущих планов находятся практики/аттестация, поэтому его числовой итог может быть нулём до задания норм.**

## Уточнения без изменения программы

В каждой группе `overrides` адресует исходную строку и семестр МУПа. Например, для строки 43 во втором семестре:

```json
"overrides": {
  "43:2": {"hours": [0, 90, 0]},
  "105:8": {"work_hours": {"N": 20}}
}
```

Числа выше — пример синтаксиса, не предлагаемые нормативы. `hours` — лекции, практические, лабораторные для указанного семестра. `work_hours` — явные часы в полях H:S; используйте для руководства/аттестации. Для K и L должны соблюдаться согласованные формулы, иначе проверка отклонит результат. Дополнительно поддерживаются `name`, `credits`, `language`, `exclude: true`. Если одна и та же настройка задана группе и после объединения участвуют другие группы, генератор разделяет разные наборы настроек.

Чтобы исключить все семестры конкретной исходной строки:

```json
"exclude_rows": [49]
```

Словарь `aliases` задаёт проверенные соответствия названий:

```json
"aliases": {
  "example_course": ["Проверенное название на русском", "Verified English name"]
}
```

Для явного распределения используется ключ дисциплины из `manifest.json`:

```json
"routing": {
  "example_course": {"sheet": "Новое направление", "payment": "main"}
}
```

`payment`: `main` или `hourly`. Одно направление не может одновременно входить в оба свода. Поле `sheet` здесь задаёт название направления в строках свода; дополнительные листы не создаются.

Браузер сохраняет `students_by_year`, `exclude_rows` и `overrides` исходных групп из `kini_config.json`, если совпадают имя группы и исходный файл. Для новой или переименованной группы эти специальные настройки автоматически не переносятся; используйте CLI-конфигурацию, если они нужны. Общие `aliases` и `routing` применяются и при запуске в браузере.

## Проверка

Полная проверка всех доступных МУПов из `input/` и `.kini-app/uploads/` без изменения исходников:

```sh
python verify_project.py
```

Результаты — в `verification/`. Одинаковые загруженные книги проверяются один раз по SHA-256. Год набора берётся из шапки, а не из имени файла. Проверка сохранённых значений формул не заменяет полный пересчёт исходной книги в Excel.

```powershell
python -m unittest test_kini test_webapp -v
```

Проверяются сохранность дисциплин и кредитов, объединённые ячейки, альтернативы, контингент потока, все формулы/кэши созданных книг, единственный лист `Расчет`, отсутствие межлистовых ссылок, оформление заголовков, итоги по каждому виду нагрузки и пересчёт после изменения числа студентов. Отдельно проверяются новые МУПы со сдвигами столбцов, шестью семестрами и формулами без кэша, несколько листов, ошибочные файлы, а также HTTP-загрузка, запуск, скачивание архива и сохранение настроек. Тесты создают собственные временные книги. Дополнительно сам генератор проверяет формулы и контрольные разности перед сохранением каждой книги.

Необязательная проверка настоящего браузера: `python browser_smoke.py` (нужны пакет `playwright` и установленный Microsoft Edge). Она проверяет загрузку нового МУПа, обязательные поля, два расчёта, скачивание и мобильный вид. Снимки сохраняются в `.kini-app/preview/`, контрольные книги — в `output_browser/`.

Известные несоответствия МУПов не исправляются молча: например, пустое название LOG, несовпадение суммы дисциплин с итогами CS и PE, несогласованные часы и распределения по семестрам отражены в журнале. Сравнение с утверждёнными нормами и визуальная проверка печати в настольном Excel остаются отдельными проверками.
